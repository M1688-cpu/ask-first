# ask-first

[English](README.md) | [简体中文](README.zh-CN.md) | 日本語 | [Français](README.fr.md) | [Deutsch](README.de.md) | [Español](README.es.md) | [Português](README.pt.md)

行動する前にまず尋ねる、2つの agent スキル。

`clarify-first` は、タスクが実装できるほど具体的になるまで一問ずつ質問し、作業開始前にブリーフを確認させてから着手します。`knock-first` は、agent がテストのためにデスクトップを操作する前に、あなたがパソコンを使っているかを確認し、許可を取ってから実行し、終わったらすぐに通知します。

どちらの問題も利用者からは同じに見えます。agent が推測で動いて、推測が外れる。先に尋ねるほうが、作り直すより安い。

## インストール

[skills CLI](https://skills.sh) がホストの検出を担当します。Claude Code、Codex、Cursor、Gemini CLI、GitHub Copilot、opencode、Amp など、対応するすべてのホストに対応します：

```bash
npx skills add M1688-cpu/ask-first -g
```

このリポジトリのインストーラを使うこともできます。マシン上の agent を検出して、それぞれへコピーします（`--all` は対応 agent 全部、`--list` はプレビュー、`--remove` はアンインストール）：

```bash
git clone https://github.com/M1688-cpu/ask-first.git
bash ask-first/install.sh
```

Claude Code ではプラグインとしてもインストールできます：

```text
/plugin marketplace add M1688-cpu/ask-first
/plugin install ask-first@ask-first
```

手動コピーの場合、各 agent が読み取るフォルダは以下のとおりです：

| Agent | スキルフォルダ |
| --- | --- |
| Claude Code | `~/.claude/skills` |
| Codex | `~/.codex/skills` |
| Cursor | `~/.cursor/skills` |
| Gemini CLI | `~/.gemini/skills` |
| opencode | `~/.config/opencode/skill` |
| Amp | `~/.amp/skills` |
| OpenClaw | `~/.openclaw/skills` |
| ZCode | `~/.zcode/skills` |
| オープン形式を読む agent 全般 | `~/.agents/skills` |

インストール後、スキルは条件が一致すると自動で発動します。名前を指定して呼ぶこともできます。

## clarify-first

曖昧な依頼を推測で処理する agent は、自信満々で間違ったものを作ります。このスキルはまず尋ねさせます。

発動条件：依頼の目標、範囲、成果物、重要な判断のどれかが複数の読み方を持つとき。明確で小さな機械的な依頼は素通りし、理解した内容を一文で復唱するだけです。

インタビューの流れ：

1. 一度に一問。各質問には 2-4 の選択肢と推奨回答があり、たいていはクリック一回で済みます。
2. 追問はあなたの回答から生まれるため、チェックリストを機械的にこなすのではなく収束していきます。
3. コードベース、ドキュメント、ウェブで調べられることは一切聞きません。意図、好み、制約など、あなただけが決められることだけを聞きます。
4. 上限はおよそ 7 問。それを超えるなら、agent は間違ったことを聞いています。
5. 確信が 95% に達したらブリーフを書きます：目標、対象内、対象外、成果物、前提。承認後に作業が始まります。

```text
あなた： サイトにダークモードを追加して
agent：  どの部分ですか？ サイト全体ですか、それとも閲覧ページから先ですか？
        （推奨：閲覧ページから。読み時間の 80% はそこです）
あなた： 閲覧ページ
agent：  システムの外観設定に従いますか、独自のトグルを付けますか？
        （推奨：システムに従う。維持する部品が一つ減ります）
あなた： システムに従う
agent：  ブリーフ：閲覧ページにダークパレット、システム外観に追従、
        管理画面は変更なし、パレットは theme.css へ。開始しますか？
        [はい / 変更する]
```

## knock-first

マウスを動かしタイピングするテストは、そのマシンを使っている人と衝突することがあります。テストが失敗するだけならまだ軽い方です。編集中のデータが消えたり、誤クリックしたりする方が深刻です。このスキルは agent に確認させ、尋ねさせ、実行させ、返却させます。

発動タイミング：デスクトップを接管するあらゆる場面。スクリーンショット、ビルドしたアプリの起動、入力のシミュレーション、テストのためのウィンドウ操作。

サイクル：

1. 検出：スクリプトがキーボードとマウスのアイドル時間、最前面のアプリ、会議やメディアアプリの再生を確認し、あなたが在席していそうか報告します。キーボードを動かさず動画を見ている人も在席とみなします。
2. 要求：一つのダイアログで検出結果、実行予定の操作の正確なリスト、所要時間の見積もりを示します。選択肢は、実行、このセッションでは以後聞かない、今はやめる。同意は現在の会話にのみ存在し、どこにも書き込まれません。
3. 実行：リストに載った操作のみ。リストにない操作は戻って再度尋ねます。
4. 返却：音付きの macOS 通知と、チャット内の結果サマリーで、マシンが戻ってきた瞬間がわかります。

```text
agent：  ただいま Xcode 作業中です（アイドル 40 秒）。デスクトップを約 3 分
        使います：ビルドしたアプリを開く、1280x800 にリサイズ、スクリーン
        ショット 3 枚、検索語を 1 回入力。よろしいですか？
        [実行 / このセッションは以後聞かない / 今はやめる]
あなた： 実行
        …… テスト実行 ……
agent：  通知を送信しました：「テスト完了：スクリーンショット 3 枚保存」
        チャット内：検索のクラッシュは再現せず、スクリーンショットは
        artifacts/ にあります。パソコンをお返しします。
```

## 動作環境

`clarify-first` は質問できる環境ならどこでも動きます。質問ダイアログのないホストでは、チャットでの質問に切り替わります。`knock-first` のスクリプトは macOS のインターフェース（`ioreg`、`lsappinfo`、`osascript`）を使います。他のプラットフォームでは検出は常に「在席」となり、agent は毎回尋ねます。スクリーンショットには、agent をホストする端末への画面収録の権限が必要です。
